# 前端资源接入规范

> 适用：`frontend/`（Vue3 + TS + Vite）。本文件是 **R0 视觉基座** 的产出与后续（R1+）新面板/新皮肤的接入约定。
> 相关文档：[SWF前端逻辑还原/11-通用组件与皮肤库.md](./SWF前端逻辑还原/11-通用组件与皮肤库.md)、[前端美术资源清单.md](./前端美术资源清单.md)、[复刻对照表.md](./复刻对照表.md)。

## 0. 两条硬要求（不可违反）

| # | 要求 | 含义 | 落地 |
|---|---|---|---|
| 1 | **交互以 AS 为准** | 任何面板/控件的行为（点击→发什么命令、字段、状态机、文案）必须回溯 `tools/export/**/scripts/*.as` 的原版实现；重写版只做等价翻译，不得凭直觉发明交互 | 每个面板在 `docs/SWF前端逻辑还原/0X-*.md` 里能查到对应 AS 类与后端函数；命令链路走 `src/api/*`，状态在 `src/stores/*` |
| 2 | **美术以原版为准** | 视觉一律复用原版贴图，禁止自绘替代、禁止新增配色体系；不得为“好看”自造按钮/面板样式 | 贴图统一走 `/images/...` 或 `src/assets/img.ts` 构造器；皮肤用 `src/styles.css` 的 `.u-*` 类，命名遵循原版资源族 |

> 补充：**只增不改**。新增皮肤/组件只允许“新增文件”或“向既有文件追加类/规则”，不得删除文件、不得改动既有玩法逻辑、面板行为与文案。

## 1. 资源绑定三机制与落地做法

原版 Flash 通过三条路径把 `images/**` 贴图绑定到界面（见 11 号文档 §3.1）。重写版按资源性质择一落地：

### 机制 A — 编译期内嵌 `[Embed]`（原版 `*__embed_css_*.as`）
- **原版**：`[Embed(source="/_assets/<ID>_<类名>.png")]`，供 Flex 样式类引用。
- **重写版做法**：对应“**固定单个贴图**”的静态皮肤。写进 `src/styles.css` 的 `.u-*` 类，URL 直接用字面量 `/images/<族>/<名>.png`。例：
  ```css
  .u-modal { border-image: url('/images/board_popup.png') 10 10 10 10 fill / 12px round; }
  ```
  这些字面量会被 `check:assets` 第 1 段核对（缺失即报错）。

### 机制 B — 具名链接类（原版 `symbols.csv` → `DefineSprite_/BitmapAsset` 类）
- **原版**：`symbolClass/symbols.csv` 把字符 ID 映射为类名，运行时 `getDefinition("<类名>")` 取类实例化。
- **重写版做法**：对应“**按逻辑键取图标**”的场景。在 `src/assets/img.ts` 写**具名构造器**函数，把业务键（bid/sid/tid/gid/face…）翻译成 `/images/...`。例：`soldierIcon(sid)`、`techIcon(tid)`、`heroFace(sex, face)`。
  构造器内部的模板串会被 `check:assets` 第 2 段提取为动态规则。

### 机制 C — 运行时拼 URL（原版 `Global.getImagePathFunc() + "images/…"`）
- **原版**：`ExternalInterface.call("getImagePath")` 拼出 `images/<族>/<名>.png|jpg`。
- **重写版做法**：对应“**数量大、命名规则化的族**”（如 `item_{gid}`、`pack_{image}`、`armor/{id}`、`achievement/{id}`）。同样收口到 `img.ts`，**禁止在组件里散落字符串拼接**（统一 base、便于核对缺失）。

> 统一入口 `img(rel)`：把相对路径拼成 `${IMAGES_BASE}/${rel}`，避免重复 `/`。所有构造器最终都应 `return img(...)`。

## 3. 新面板标准模板（SkinDialog + api/ + stores/ + 组件 + CityView 接线）

五段式，严格分层（**面板组件内不直接调 store**，数据与事件由 `CityView` 注入/回传）：

### ① `src/api/<域>.ts` — 纯请求层
```ts
import http from './http'
import type { XxxInfo } from '@/types'

/** GET /cities/:cid/xxx/info —— 对齐 backend ...  */
export async function getXxxInfo(cid: number): Promise<XxxInfo> {
  const { data } = await http.get<XxxInfo>(`/cities/${cid}/xxx/info`)
  return data
}
```

### ② `src/stores/<域>.ts` — 状态 + 动作（Pinia setup store）
```ts
export const useXxxStore = defineStore('xxx', () => {
  const info = ref<XxxInfo | null>(null)
  async function load(cid: number): Promise<XxxInfo> {
    info.value = await xxxApi.getXxxInfo(cid)
    return info.value
  }
  return { info, load }
})
```

### ③ `src/components/XxxPanel.vue` — 皮肤组件（`<script setup lang="ts">`）
- 用 `SkinDialog` 做外壳（九宫 + 标题条 + 关闭钮），内容进默认插槽，按钮进 `#footer`。
- `defineProps<{...}>()` 显式类型（禁用 `any`）；`defineEmits` 回传业务事件；**不 import store**。
- 皮肤类只用 `.u-*`（标题 `.u-title`/关闭 `.u-close`/按钮 `.u-btn--*`/页签 `.u-tab--*`/列表 `.u-list-item`/表格 `.u-table--lined` 等）。
```vue
<script setup lang="ts">
import type { XxxInfo } from '@/types'
import SkinDialog from '@/components/SkinDialog.vue'

const props = defineProps<{ info: XxxInfo | null; loading: boolean; error: string; busy: boolean }>()
const emit = defineEmits<{ (e: 'do', id: number): void; (e: 'close'): void }>()
</script>

<template>
  <SkinDialog title="面板标题" @close="emit('close')">
    <p v-if="props.loading" class="u-hint">加载中…</p>
    <p v-else-if="props.error" class="u-hint is-error">{{ props.error }}</p>
    <template v-else>
      <!-- 内容：u-tabs / u-list-item / u-table--lined 等 -->
    </template>
    <template #footer>
      <button class="u-btn u-btn--confirm" :disabled="props.busy" @click="emit('do', 1)">确定</button>
      <button class="u-btn u-btn--cancel" @click="emit('close')">取消</button>
    </template>
  </SkinDialog>
</template>
```

### ④ `src/views/CityView.vue` — 接线（打开/关闭状态 + run 包裹 + 事件）
```ts
const store = useXxxStore()
const showXxx = ref(false)
const xxxLoading = ref(false)
const xxxError = ref('')

async function openXxx(): Promise<void> {
  showXxx.value = true
  xxxError.value = ''
  xxxLoading.value = true
  try {
    await store.load(activeCid.value)
  } catch (e) {
    xxxError.value = errorMessage(e)
  } finally {
    xxxLoading.value = false
  }
}
function closeXxx(): void {
  showXxx.value = false
}
```
```vue
<XxxPanel
  v-if="showXxx"
  :info="store.info"
  :loading="xxxLoading"
  :error="xxxError"
  :busy="xxxBusy"
  @do="onXxxDo"
  @close="closeXxx"
/>
```
- 写操作统一包一层 `runXxx(fn)`：置 `busy`、`try/catch` 走 `errorMessage(e)`、成功后按需 `city.refreshResources(activeCid)`；失败文案经 HTTP 400 message 展示。
- CSS 文案（如 `加载中…`/`确定`）直接写在模板，或由 props 传入；中文以 `src/lang/zh-CN.ts` 为准优先取 `zhCN.*`。

## 4. `check:assets` 四段输出解读与用法

```
npm run check:assets            # 缺失字面量引用时退出码 1
node scripts/check-assets.mjs --list   # 第 3 段列出全部未使用资源
```

| 段 | 名称 | 含义 | 何时关注 |
|---|---|---|---|
| 1 | 字面量引用核对 | 扫描 `src/**/*.{ts,vue,tsx,css}` 的 `/images/...` **字面量**，与 `public/images` 实际文件比对 | 出现 `MISSING` 即退出码 1，必须修 |
| 2 | 动态规则核对 | 从 `img(\`前缀${...}后缀\`)` 提取模板→正则，统计各规则命中的资源数 | 确认新构造器已生效（出现对应规则） |
| 3 | 未使用资源 | `public/images` 中未被任何字面量或规则命中的文件（候选冗余） | 判断族属是否已接入；`--list` 看全部 |
| 4 | AS 交叉核对 | 读 `../tools/asset-index.json` 的 `cross.referencedNotInSrc`，列 AS 已引用但未接入的资源族 | 排 R1 接入优先级；**本段不影响退出码** |

**第 4 段输出样例**：
```
=== 4) AS 已引用、重写版尚未接入的资源族（源：../tools/asset-index.json → cross.referencedNotInSrc） ===
  族数 N；AS 引用合计 R 次；前端已有文件（frontCount>0，可直接接入）M 族；⚠ 前端无文件 K 族
  按 AS 引用次数降序（前 40）：
    refCount= 324  ✔ 可直接接入 frontCount=476  influence
    refCount=  ..  ⚠ 前端无文件                  assets
    ...
```
- `✔ 可直接接入 frontCount>0`：`public/images` 已有文件，只差在 `img.ts` 建构造器 + 组件引用。
- `⚠ 前端无文件 frontCount=0`：原版 AS 引用但前端未拷贝该族，需先补资源，再谈接入。
- **退出码语义不变**：仅第 1 段字面量缺失才 `exit 1`；第 3/4 段打印大量未接入族属正常。
