## 一、目标与铁律

**目标**：用 Vue 3 重写原版 Flash 客户端的全部界面，**视觉与交互 1:1**，且**一律复用 `frontend/public/images/` 中的原版美术资源**，不自绘替代物料。

**铁律（不可违反）**
1. **只复用不重绘**：所有图片一律走 `/images/...` 原版路径或 `src/assets/img.ts` 构造器；缺资源时**先找原版同名资源**，确实不存在才降级并在文档登记。
2. **不改后端**：本计划内只消费既有 REST 接口。若某界面依赖后端缺失能力，**另立后端批次**，不在本计划内"顺手改"。
3. **视觉对齐原版**：弹窗/按钮/页签/图标使用原版九宫格与三态贴图（已封装的 `.u-modal`/`.u-title`/`.u-close`/`.u-btn--*`/`.u-tab`/`.nav-btn`），不引入新配色体系。
4. **不修原版怪癖**：原版文案（含"成功提示走 400"）一律照实展示。
5. **已排除项不做**：联盟、好友、聊天、排行、竞技场、洛阳、结婚、防沉迷、渠道支付（与后端裁剪保持一致）。

## 二、现状基线

### 2.1 技术基线
- Vue 3.5 + TS 5.6 + Pinia + vue-router + axios + Vite 5，**无 UI 库**
- 单页编排：[CityView.vue](../frontend/src/views/CityView.vue)（`showXxx/openXxx/closeXxx` + `runX(fn)` + `errorMessage(e)`；顶栏按钮进各面板）
- 分层：`api/<mod>.ts`（axios + DTO）→ `stores/<mod>.ts`（Pinia）→ `components/*.vue`（props in / events out）
- 弹窗外壳：[SkinDialog.vue](../frontend/src/components/SkinDialog.vue)（`board_popup` + `popup_title` + `lottery_close`；已加 `overflow:hidden`）
- Canvas 渲染范式：`render/cityGrid.ts`、`render/worldGrid.ts`（high-DPI + 贴图缓存 + 命中测试）
- 核对工具：`npm run check:assets`（三段式：字面量缺失 / 动态规则命中 / 未使用清单）

## 五、阶段计划

### 阶段 0 · 基线与规范固化（前置，无 UI 改动）
**任务**
1. 冻结《资源复用映射表》（第四节）与《界面覆盖对照表》（第三节）作为唯一索引
2. 把 `npm run check:assets` 纳入提交前检查（缺失即失败）；每新增一条动态规则须同步登记
3. 固化"新增面板模板"：`SkinDialog` + `.u-btn--*`/`.u-tab` + `api/store/组件` 三层 + `CityView` 接线 + 切城复位
**验收**：`npm run check:assets` 退出码 0；映射表与代码一致（新增资源族有登记）

### 阶段 1 · 存量界面原版化（**不动玩法，风险最低，优先做**）
**任务**（每项只换视觉/补贴图，不改接口与逻辑）
1. **抽奖盘面**：改用 `lottery_bg/title/turntable/start*/restart*/get*/pay*` 全套，替换现有自绘盘面与文字按钮
2. **外城城防**：器械 `did` → `defence_*` 贴图（1 陷阱/2 拒马/3 箭塔/4 滚木/5 擂石）
3. **世界地图 UI**：`map_*`/`sign_*`/`ditu_b*`/`bt_*`/`move_*` 用于边框、缩放/移动按钮、标记
4. **通用 Tooltip**：道具/装备/武将悬浮详情改用 `board_tip`/`board_hint`（对应原版 `Tooltip` 包）
5. **镶嵌界面**：`embed_*` + `item_default_*`（空珠位/锁定态）
6. **科技/成就/任务奖励图标**：任务奖励补 `item_{gid}`/`armor/{id}`（与 M8 奖励类型对齐）
7. **顶栏补全**：`function_*_blink`（新邮件/任务闪烁）、`topbutton_report*`（战报入口贴图）、`*_alarm` 红点
8. **城池网格补全**：按 `cfg_buildings` 全量 bid 补齐 `building_*`/`inbuilding_*` 映射（现仅 11 条）
9. **内政/资源图标补齐**：`terrain_*`、`mycity_*` 等
**验收**：`vue-tsc` + `npm run build` 通过；浏览器冒烟逐面板对照原版截图；`/images/*` 无 404；未使用资源数下降（记录前后对比）

### 阶段 2 · 后端已就绪的缺口界面
**任务**
1. **背包道具界面**：`GET /goods` + `POST /goods/use`（`pack_*`/`item_*` 已备）
2. **增益状态面板**：`Buffer` ↔ `user_buffers`（**先确认后端是否暴露查询接口**，无则登记为后端补缺）
3. **玩家资料（UserInfo）**：`/auth/me` + 城池/战功统计，头像用 `player/`
4. **统计/战功报表（Stat）**：战功/声望数据 + `medal_*`
**验收**：同阶段 1，并为每个界面补一条 `check:assets` 规则

### 阶段 3 · 战斗表现层（原版 SWF 动画的 Web 降级）
**任务**
1. 用**后端 17 字段逐回合战报**驱动 Canvas/CSS 演出（对齐原版 `battleRound` 回合制）
2. 序列帧：`chibi/`（Q版）/`battle/` 逐帧播放；`arrow_*` 用 `.gif`（`arrow_1~4.gif` 已存在）
3. **不可 1:1 项登记**：`.azp`（18）/`.swf`（10）无法在 Web 播放 → 静态首帧或跳过，产出"失真降级清单"
**依赖**：M7 战斗引擎已提供逐回合数据（`battle_rounds`）
**验收**：逐回合可回放；降级项清单确认；性能（帧率/内存）不劣化

### 阶段 4 · 未实现玩法界面（**需先确认排期**）

**验收**：同阶段 1；未就绪项明确标注"阻塞于后端"

### 阶段 5 · 资源治理与构建体积
**任务**

**验收**：`npm run build` 通过且产物自洽；核对脚本仍 0 缺失
