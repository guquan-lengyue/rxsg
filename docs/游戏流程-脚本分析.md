# 热血三国 · 游戏流程（反编译脚本分析）

> 依据：`tools/export/` 下 FFDec 反编译的 AS3 源码（主客户端 `BloodWar/scripts`、共享库 `bloodcommon.swc`、战斗引擎 `BloodBattle`/`ChibiBattle`）。
> 每条流程均附 文件:行号 证据（路径省略前缀 `tools/export/`）。
> 用途：为 Go+Vue3 重写版提供原版行为对照基准，**不据此修改任何已实现逻辑**。

## 0. 全流程总览

```
浏览器宿主(JS) ⇄ ExternalInterface 桥 ⇄ BloodWar.as (Flex Application 入口)
      │
      ├─ ① 启动: Preloader → applicationComplete → 注册 ~20 个 addCallback → getSwfPassFile 加载验证码
      ├─ ② 登录: LoginDialog → doLogin(RemoteObject) → checkQueue(排队) → 进入游戏
      ├─ ③ 初始化: initGame → loadGlobalData/loadUserInfo → getCityInfo → showAllPanel(默认内城)
      ├─ ④ 主循环: 内城(CityInnerPanel) ⇄ 外城 ⇄ 世界地图(WorldPanel)
      │      ├─ 建筑: 建造/升级/拆除/加速   ├─ 科技: 书院研究
      │      ├─ 征兵: 兵营队列             ├─ 出征: 选将选兵→行军→战斗→战报
      │      ├─ 武将: 酒馆招募/上阵/历练    └─ 资源: 产出/税收/市场
      └─ ⑤ 外围: 聊天/联盟/任务/成就/排行/商城/邮件/活动(竞技场·过关斩将·洛阳战·结婚)
```

通信协议核心：所有业务走 `Command.as` / `BattleCommand.as` 的 RemoteObject `sendCommand`，报文 = `[uid, sid, COMMAND_TYPE_*, module/action, command, ...params]`（加密）。

## 2. 客户端-服务器通信协议

### 2.1 报文结构（Command.as）
```
sendGlobalCommand(module, action, ...params)
  → [uid, sid, COMMAND_TYPE_GLOBAL, module, action, ...params] → 加密 → RemoteObject "sendCommand"
```
- 组装与发送：`BloodWar/scripts/Command.as:134-181`
- 回包分发：按 `COMMAND_TYPE_DIALOG` / `COMMAND_TYPE_GLOBAL` 拆到 `onDialogCommand` / `onGlobalCommand`：`Command.as:312-338`
- 战斗通道同构（独立 `BattleCommand`，走战斗服 URL）：`BattleCommand.as:134-182,289-338`

### 2.2 类型常量（Define.as:26-32）
| 常量 | 值 | 用途 |
|---|---:|---|
| `COMMAND_TYPE_CITY` | 0 | 城池域命令（RT_CITYINFO=0 城池信息回推） |
| `COMMAND_TYPE_DIALOG` | 1 | 弹窗域（打开某建筑/面板时按 dialog id 回填） |
| `COMMAND_TYPE_GLOBAL` | 2 | 全局业务命令（city/troop/report… action 路由） |

### 2.3 对话框 ID（Define.as:74-80）
| 常量 | 值 | 用途 |
|---|---:|---|
| `ID_CRDATE_BUILDING` | 100 | 建造建筑选择弹窗 |
| `ID_REPORT_DIALOG` | 101 | 战报弹窗 |
| `ID_TACTICS_DIALOG` | 102 |  tactics/计策弹窗 |
| `ID_CREATE_ROLE` | 103 | 创建角色弹窗 |

### 2.4 全局命令路由
`BloodWar.onGlobalCommand` 按 action 分发到 `city` / `troop` / `report` 等面板：`BloodWar.as:5501-5533`。

## 3. 核心玩法闭环

### 3.1 建筑（建造/升级/队列/拆除）
1. 点击空地 → `CreateBuildingDialog` 发 dialog 命令 `getAllValidBuilding` 拉取可建列表：`Building/CreateBuildingDialog.as:164-169`
2. 确认 → 组装 `[City.cid, inner, x, y, bid]` 发全局命令 `city/startUpgradeBuilding`（建造与升级同接口）：`CreateBuildingDialog.as:261-269`
3. 队列面板 `BuildingListDialog` 遍历 `City.buildingList`，由 `BuildingState.state` 计算 `statename/targetlevel/lefttime/endtime`：`Building/BuildingListDialog.as:723-769`
4. 取消/拆除弹确认；加速按 `state_endtime - Global.getServerTime()` 走 `showUseGoodsDialog`（道具抵扣）：`BuildingListDialog.as:771-822`
5. 渲染：`BuildingGrid.setCityHall()` 贴图+等级标签；`mHilight/mGrey` 时把 ColorMatrixFilter 应用到建筑位图/空地基：`Building/BuildingGrid.as:146-166,245-260`

### 3.2 科技（书院）
1. `CollegeDialog` 收到 `onBuildingInfo`，识别 `ID_BUILDING_COLLEGE` 后 `mTechnicPanel.onLoadTechnicInfo(param1[2])` 载入科技树：`College/CollegeDialog.as:82-88`
2. 开始研究 → 全局命令 `startUpgradeTechnic`（含书院坐标参数+科技 ID）：`CollegeDialog.as:102-107`；停止 → `stopUpgradeTechnic`：`CollegeDialog.as:75-80`
3. 上限校验 `TECHNIC_MAX_LEVEL=10`（Define.as）：`College/CollegeTechnicItem.as:277-289`；点击升级/停止闭环：`CollegeTechnicItem.as:762-776`

### 3.3 征兵（兵营）
1. `ArmyDraftDialog.onDraft()` → `mArmyDialog.startDraftQueue(...)`：`Army/ArmyDraftDialog.as:1002-1009`
2. 面板实时计算 `mDraftTime = count × draft_time` 与最大可征数（资源/人口约束）：`ArmyDraftDialog.as:1044-1049`
3. 命令参数 `[inner, x, y, soldierID, count, doubleResource]` 发向 `ID_BUILDING_ARMY`：`Army/ArmyDialog.as:322-332`（注：`doubleResource` 为资源翻倍道具开关）
4. 队列倒计时 `onTimer()` 递减，完成后 `reloadBuildingInfo()` 刷新：`Army/ArmyDraftPanel.as:341-363`

### 3.4 出征与战斗
1. 出征目标选择在世界地图（见 §5.1），部队/攻防编排在 `Troop/BattleDialog`（记录攻防城、英雄、距离、回合数、战斗类型）：`Troop/BattleDialog.as:66-80,132-158`
2. 部队项按 `ARMY_ITEM_ATTACK/DEFENCE/RESIST` 模式分发 `onChangeAttackTarget/onChangeDefenceTarget/onChangeResistTarget`：`Troop/BattleArmyItem.as:174-182,243-276`
3. 战斗结算走独立 `BattleCommand` 通道（战斗服 URL 在登录成功后获取，§1.2）；回包进 `reportDialog.onCommand` / `troopDialog.onCommand`：`BloodWar.as:5501-5533`
4. 动画层：`ChibiBattle`（Q 版回合演出）+ `battleRound.swf`（round_1~6 回合数）+ `heroBattleEffect.swf`（Baoji 暴击/Gedang 格挡/Poji 破击/Shanbi 闪避 四特效，按战斗事件触发）
5. 战报：`Report/` 包 + `ID_REPORT_DIALOG=101`

### 3.5 武将
1. 招募：`HotelDialog` 发 `recruitHero` 到 `ID_BUILDING_HOTEL`（酒馆）：`Hotel/HotelDialog.as:271-278`；重置/征辟同包：`HotelDialog.as:194-226`
2. 属性面板：`Hero/HeroDetailDialog`（kingLevel/姓名/坐标）：`Hero/HeroDetailDialog_inlineComponent1.as:57-63`
3. 历练/增益：`HeroBufferDialog.reLoad(hid)` 请求 `hero/getHeroBuffer`，打开 praise/largess 面板：`Hero/HeroBufferDialog.as:426-437`
4. 三职位（主将/城守/军师）对应 `cities.general_hero_id/chief_hero_id/counsellor_hero_id`（重写版 DB 字段同源）

### 3.6 资源与税收
- 顶栏资源/队列倒计时：`Bar/BuildingItem.onTimer()` + `Utils.MakeTimeLeftString(mLeftTime)`：`Bar/BuildingItem.as:340,830`
- 市场/客栈/官署交互（加速售卖、任务奖励、武将历练加速）经 `sendDialogCommand(..., ID_BUILDING_MARKET/HOTEL/OFFICE, ...)`：`BloodWar.as:6602-6647`

## 5. 专题结论

### 5.1 世界地图（World/）
- 坐标体系：`GRID_DISTANCE=60000`（`Define.as:8`）——地图格用大整数坐标，行军距离/时间由此折算。
- 渲染参数（`World/WorldPanel.as`）：等距瓦片偏移 `GRID_OFFSET_X=54 / Y=27`（:486-488），视口加载范围 `LOADRANGE_X/Y=20`（:746-748），中心格 `CENTER_GRID_X=314 / Y=250`（:1284-1290）——**按需分块加载**，非整图。
- 点击地块：`World/WorldAction51Dialog.as` 按目标类型弹出 `CityMergeDialog`（合并城）、`XuanZhanDialog`（宣战）等——出征/占领/掠夺入口即在此发起（task=3 掠夺 / 4 占领，与重写版 `army.TaskPlunder/TaskOccupy` 一致）。
- 行军箭头：`arrow_1~4`（上/右/下/左，见美术文档 §10）叠加在行军线上。

### 5.2 Union 与 Chat
联盟聊天不是独立通道：Union 面板把消息交给 `ChatPanel`，以 `CHANNEL_UNION=1` 经 **ChatSocket**（区别于业务 RemoteObject 的长连接）发送，服务器命令 `PROC_CHAT_UNION_CHAT=5`。

### 5.3 Task/成就/排行数据来源
均为 dialog 命令按需拉取（`sendDialogCommand` + 对应 dialog id 回填），无独立推送；与主城状态刷新解耦。

### 5.4 运行时加载外部 SWF 的包
统一走 `Loader/SwfLoader.loadSwf(url)`（`Loader/SwfLoader.as:43`）：
- `ArenaDialog:1072`、`GuoGuanZhanJiangDialog:1386`、`MarryKingExpr:1707` → `swf/battleRound.swf`
- 战斗特效/行军动画（heroBattleEffect/trooper/arrow/loading）同机制（宿主页面或 `Nireus.LoadSwfManager` 加载）

### 5.5 不明包定论
- `Nireus` = 资源加载框架（非玩法）；`Adult` = 防沉迷/实名验证弹窗；`secret` = 导出目录中无独立包（前缀搜索无文件），判定为误列或已内联。

## 6. 与重写版（Go+Vue3）对照要点

| 原版机制 | 重写版现状 | 差异说明 |
|---|---|---|
| 20 建筑 bid（`Define.as` 枚举） | 10 建筑 bid（后端硬编码 1官府…10校场） | **不同源**；种子已按重写映射+曲线重映射（见美术文档 §9.1 警示） |
| RemoteObject 加密报文 + 独立 ChatSocket + 战斗服 URL | REST API + 内存 Session | 重写版为无状态简化；命令→路由一一对应 |
| 客户端算 `count × draft_time`、`endtime - serverTime` | 服务端 `realDraftSeconds`/`SettleDraft` 惰性结算 | 时间基准改为 DB `NOW()`，倍速 `GAME_SPEED_RATE=1` 与原版一致 |
| 三职位字段 general/chief/counsellor | `cities.general_hero_id/chief_hero_id/counsellor_hero_id` | 字段同源，`speedRate` 取职位 bravery 与原版 `getSoldierSpeedRate` 对齐 |
| 历练 `hero/getHeroBuffer` | `hero.ExprExpPerHour=40` | 常量已对齐 |
| `TECHNIC_MAX_LEVEL=10`、`BUILDING_MAX_LEVEL=10` | `building.maxLevel()` 按城型 10~20 | 重写版按城型放宽，若 1:1 需回归 10 |
| 防沉迷（Adult）/创建角色（ID_CREATE_ROLE） | 未实现 | 原版平台侧系统，重写版按需求裁剪 |
