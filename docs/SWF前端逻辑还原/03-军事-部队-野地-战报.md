## 0. 命令通道与回包路由（本域共性，先建立闭环基础）

本域两条命令通道（`Command.as`）：

| 通道 | 方法签名(file:line) | 报文头 | 用途 |
|---|---|---|---|
| 全局命令 | `sendGlobalCommand(module, action, params, useService2)` — `scripts/Command.as:134` | `[uid, sid, COMMAND_TYPE_GLOBAL=2, module, action, ...params]` | Troop/Battle/Report/World/armyDraft 等按「模块.动作」寻址 |
| 弹窗命令 | `sendDialogCommand(name, id, buildingParam, params, subid)` — `scripts/Command.as:237` | `[uid, sid, COMMAND_TYPE_DIALOG=1, cid, id, buildingParam, subid, name, ...params]` | Army 兵营(ID=9)/Ground 校场(ID=8) 等按「建筑ID + 子命令号」寻址 |

- 命令类型常量：`COMMAND_TYPE_DIALOG=1` / `GLOBAL=2`（`bloodcommon.swc/library_swf/scripts/Define.as:28,30`）。
- 建筑 ID：`ID_BUILDING_GROUND=8`（`Define.as:48`）、`ID_BUILDING_ARMY=9`（`Define.as:50`）。
- 全局命令回包统一进入 `BloodWar.onGlobalCommand(action, command, data)`（`scripts/BloodWar.as:5422`），按 `action` 分派：
  - `action=="troop"` → `troop` 模块：`kickTroop`/`getTroopDetail`/其余分别派发到弘胪/`troopDetailDialog`/`troopDialog`（`BloodWar.as:5505-5526`）。
  - `action=="report"` → `dialogManager.reportDialog.onCommand(command,data)`（`BloodWar.as:5528-5532`）。
  - `action=="battle"` → `getBattleActiveState`→`battleActiveStatePanel.onBattleActiveState`、`getLuoyangEvent`→`onLuoYangEventData`、`getBattleNetUrl`→跨服（`BloodWar.as:5693-5722`）。
  - `action=="world"` → `getFavouritesList`/`deleteFavourites` 走 `campaignFavouritesDialog.onGetFavouritesListCommand`，其余走 `worldPanel.onCommand`（`BloodWar.as:5458-5468`）。
  - `action=="armyDraft"` → `dialogManager.armyDialog.mDraftDialog.onCommand(command,data)`（`BloodWar.as:5885-5888`）。
- 弹窗命令回包进入建筑对话框 `onBuildingInfo(data, subid)`（详见各建筑对话框）。

> ⚠ `BattleDialog.getBattleData`/`getBattleReport`/`setSoldierTactics` 走的是 **`troop` 模块**（非 `battle` 模块），见 `Troop/BattleDialog.as:1508/1576/1969`。

## 4. 状态机与流程

### 4.1 征兵队列状态机（`ArmyDraftState.state`）
`state=0` 排队中 → `state=1` 征募中（`ArmyDraftPanel.onDraftInfo` 仅当 `data[0].state==1` 才把首位放入「当前征兵」`mDraftingItem`，其余入队列容器，`ArmyDraftPanel.as:453`）→ 完成后入城。UI 计时：`ArmyDraftItem.onTimer`（`:326`）逐秒减 `time_left`，≤0 返回 false → `ArmyDraftPanel.onTimer`（`:341`）5s 后 `mArmyDialog.reloadBuildingInfo()`。队列槽位数 = 兵营等级（`draftQueueContainer.numChildren != mLevel` 时重建，`ArmyDraftPanel.as:617`），`(mCurrentQueue/mLevel)` 显示占用。

### 4.2 部队状态机（`troop.state` 索引 `STATE_NAME_ARRAY`，6 态）
`TroopArmyPanel.onLoadData`：`state==3` 用「战斗中」占位文案且按钮为 `LABEL_NAME[1]`；`state<2` 且到达时间过期 → 5s 轮询 `getArmyTroops` 刷新（`TroopArmyPanel.as:270-288`）。`TroopDialog.onControlTroop`（`:1625`）：`state==3`→`showBattleDialog(battleid,...)`；`state∈{0,2,4}`→`callBackTroop(id,...)`。`TroopDetailDialog.showArmyDetail` 的可见性开关见 §2.2。

### 4.3 战斗流程
`showBattleDialog` → `loadBattle`（首次延时 30ms 待控件创建，`BattleDialog.as:2127`）→ `getBattleData` → 设类型/双方/武将 → `onLoadBattleReport` 首帧；每 30s `getBattleReport` 增量；玩家点格子改战术 `setSoldierTactics`；`result` 到位后 `mBattleFinished=true`，停止轮询。异常：赤壁加载失败 `Chibi_Loading`；洛阳来源关闭时回洛阳面板（`BattleDialog.as:2213-2231`）。

### 4.4 野地/校场流程
`GroundDialog.onBuildingInfo` 每次回包都刷新城池资源(1)+人口(2)；子弹窗各自 `onShow` 触发对应 `get*`（伤兵 5 / 逃兵 7 / 俘虏 9 / 抗性 4）；`CampaignDialog` 出征成功即 `visible=false` 并关闭。

## 8. 原版怪癖与注意事项

1. **征兵最大数不含金币**：`getMaxDraftCount` 只用 人口/粮/木/石/铁（`ArmyDraftDialog.as:1327`），资源表中却有金条件；`ArmyDissolveDialog` 返还按 `round(need×count×0.33)`。
2. **`conscript` 子命令号与 `getResistTactics` 同号(4)**（`GroundDialog.as:181,283`），回包 `onBuildingInfo(_,4)` 固定进抗性战术分支；原版如何区分「征募」与「抗性战术」回包 —— **待确认**。
3. **`ArmySoldierItem.createDissolveTip` 的 if 条件复制粘贴错误**：四段资源条件均判断 `mSoldierState.foodNeed > 0`（`ArmySoldierItem.as:473-488`），导致粮为 0 时木/石/铁不显示；金单独判断 `goldNeed`。此为原版 bug，重写版若 1:1 需保留或明确修正。
4. **`TroopEnemyPanel` 三字段恒被覆盖**：`union`/`hero`/`herolevel` 先赋 i18n 值后被无条件覆盖为 `TroopEnemyPanelSrc_3/4/9/10`（`TroopEnemyPanel.as:278-282`），第一个 `union` 赋值即被下一个覆盖（`:278,280`）——死代码/遗留。
5. **`compareCity` 用赋值而非比较**：`return param1.targetcid = param2.targetcid`（`TroopDialog.as:1915`，非 `==`），排序回调恒返回真值；**`compareAdd`/排序逻辑存在缺陷**但为原版行为。
6. **`allowAutoDiscard` 无回包处理**：`onGlobalCommand` 对 `command=="allowAutoDiscard"` 显式 `else if(command != "allowAutoDiscard")` 跳过（`BloodWar.as:5523`）。
7. **`ArmyDraftDialog` 双倍资源请求发在 UI 切换时**（`onChangeType`,`:1115`），并非提交时；`onShow` 打开即发一次 `onChangeType(false)`（`:1173`）——打开弹窗即产生一次全局命令。
8. **`BattleDialog.loadBattle` 首次延时 30ms**（`setTimeout(doLoadBattle,30,…)`,`:2127`）等待 `createViewChildren` 建好格子；否则立即加载。
9. **战斗回包模块归属反直觉**：战斗数据/战术走 `troop` 模块（`BattleDialog.as:1508,1576,1969`），而会战状态走 `battle` 模块（`BattleActiveStatePanel.as:2961,3108`）。
10. **`ReportListPanel.getColor` 与 `REPORT_COLOR` 长度不匹配**：`getColor(title==50)` 特判红，其余 `title<REPORT_COLOR.length` 才取色，否则白（`:444-455`）。
11. **`ReportDetailPanel.showReport` 拼 Web 战报 URL**：`Global.reportUrl+"id=…&type=report&uid=…&sid=…&useNew=true"`（`ReportDialog.as:455-459`），`from_battlenet==0` 与 `!=0` 分支调用同一 `showDetailReportFrame(false)`（`ReportDialog.as:645-652`）——两分支等价（死分支）。
12. **`Announcement` 用 `Global.cmd.sendGlobalCommand("reward","getLoginInfo")` 同时出现在 `openAnnouncement` 与 `onCreate`**（`Report/Announcement.as:1686,2652`），可能重复请求。
13. **拼写异常**：`SolderChooserPanel`（应为 Soldier）、`SolderChangePanel` 系 i18n 键、`UpdateHistorytDetailPanel`（应为 History）；重写版命名需注意对照。
14. **`AttackTacticsDialog.as` 为空文件（0 行）**：进攻战术 UI 实际内嵌于 `CampaignDialog`（`mAttackTacticsDialog` 字段 + `showAttackTacticsDialog`,`:3685`），`GroundDialog.getAttackTactics`(subid3) 回包直接给 `CampaignDialog.onGetAttackTactics`（`CampaignDialog.as:2723`）。
15. **跨服/赤壁依赖**：`Troop` 列表项对 `inChibiNet==1` 走 `chibiBattleLoader.getChibiBattle().interface4BloodWar.*`（`TroopArmyPanel.as:313`），`ReportDetailPanel` `from_battlenet==2` 同理（`:606-616`）；这些依赖独立 SWF（文档 04）与跨服网关，重写版无对应基础设施。
