## 2. 界面结构与字段

### 2.1 联盟主窗 `UnionDialog` / `NewUnionDialog`
- 布局：标题 + 页签 + 内嵌子面板容器；子面板：`unionInfo`(信息)、`unionChiefCity`(郡城)、`unionStorage`(仓库)、`unionEelation`(关系) 四块互斥显示（`NewUnionDialog.as:2055-2061 initPanelVisible`），另有 `memberListDialog`/`inviteDialog`/`applyDialog`/`introDialog`/`unionRewardDialog`/`assignLuoYangPanel` 子弹窗（`NewUnionDialog.as:3041-3049 closeAllChildPanel`）。
- 联盟信息字段（`NewUnionDialog.as:3114-3137` 绑定表达式）：
  | 显示 | 数据字段 |
  |---|---|
  | 联盟名 | `mUnion.name` |
  | 盟主 | `mUnion.leadername` |
  | 创建者 | `mUnion.creator` |
  | 成员数 | `mUnion.member + "/" + mUnionMaxMember` |
  | 名城 | `mUnion.famouscity` |
  | 排名 | `mUnion.rank` |
  | 声望 | `mUnion.prestige` |
  | 贡献 | `mUnion.donate` |
  | 公告 | `mUnion.announcement` |
  | 简介 | `mUnion.intro` |
- 回包解析（`UnionDialog.as:925-949 onLoadUnionInfo`）：`param=[0/失败提示...]`；成功时依次取 `mUnion`、`mUnionMaxMember`、`User.unionpos`，并据 `mUnion.id` 写 `User.unionid`，`User.union_pos=Utils.getUnionPos()`。
- 关系列表 `mUnionList`（`UnionDialog.as:1116-1127`）：`getUnionRelation` 回包 `[code, 列表]`，`code==0` 弹提示并关闭，否则填入。
- 成员列表列：`unionposname`(职务名)、`cityCount`、`name`、`donate`、`lefttimeStr`(踢出倒计时)、`nobilitypos`、`doName`（`UnionMemberListDialog.as:788,800,994,1016,1083,1250,1270,1376`）。

### 2.2 郡城分配 `UnionChiefCityDialog` + `UnionCityImageItem` + `AssignLuoYangPanel`
- `UnionCityImageItem`：78×60 图标项，`buildingImg` 贴 `images/building_intro_{bid+4}.png`，`buildingLabel` 显示 `mSelectItem.name`；`open==0` 时叠加灰度 `ColorMatrixFilter`（`UnionCityImageItem.as:127,209-273`）。
- `AssignLuoYangPanel`：输入玩家名 `assignTI`，按钮「确定」→ `doAssign()`；空名校验提示 `Union_Member_select_can_not_empty`（`AssignLuoYangPanel.as:295-306`）。

### 2.3 仓库 `UnionStorageDialog` + `UnionGoodsImageItem`
- `UnionGoodsImageItem`：70×70 图标项；`gid<0` 视为装备（图 `images/armor/51014.png`），否则用 `MyGoodsDialog.makeItemImageName(goodInfo)` 生成 `goodInfo.imageName`；`level` 门槛校验 `checkGoodIsOpen`（`UnionGoodsImageItem.as:164-199,353-360`）。
- Tooltip：装备→`Hero_HeroArmorPanelSrc_1`+`Union_Storage_exchange_armor_tip`；道具→`goodInfo.name/description`（`UnionGoodsImageItem.as:309-323`）。

### 2.4 外交 `UnionDiplomacyDialog`
- 8 列 DataGrid（`UnionDiplomacyDialog.as:663-759` 表头），字段含 `rank`、`member`、`leader`、`time`、`name`、`prestige`（`:426,490,897,955,977,998`）；页签含「友/中介/敌/申请列表」。

### 2.5 联盟事件 `UnionEventDialog`
- 2 列 DataGrid（`mUnionEventList`），分页 `mPage`（`UnionEventDialog.as:443-502`）。

### 2.6 鸿胪寺 `HongluPanel`
- 6 列表格（`HongluPanel.as:348-365,811-829`）：`hero`(武将)、`username`、`cid`(来源城，`Utils.makeCid`)、到达时间(`arrivetime`=endtime 文案)、剩余时间(`staytime`)、操作（查看→`onViewTroop`）。
- 头部：`mUnionName`、`mUnionTroopCount/mHongLuLevel`（形如 `(count/level)`，`HongluPanel.as:677,324`）。
- 三个开关 CheckBox：`allowCheckBox`(允许联盟增援)、`allowAntiPlunder`(反劫掠)、`allowAntiInvade`(反入侵)，勾选变更即回发命令（`HongluPanel.as:394-397,424-427,886-889`）。

### 2.7 结婚 `MarryMainPanel`
- 3 页签（`sendMarryCommand`，`MarryMainPanel.as:257-276`）：
  - case 1 → `marryKingExpr`（招亲/君主历练），`loadMarryInfo()`
  - case 2 → `marryMadam`（妻妾），`MarrySystem/loadMarryMadam`
  - case 3 → `marryChild`（子嗣），`setShowIndex(1)` + `MarrySystem/loadMarryChild`
- `MarryKingExpr`：`girlfriendArr`（候选女性，9 宫格分页）、`curGirlfriendArr`、`favor`、`proposeLeftTime`（求婚冷却，逐秒递减 `MarryKingExpr.as:2095-2110`）；`dealWithGirlfriendInfo` 解析回包；招亲战斗走 `MarryHeroBattlePanel.getBattleData(param2)`（`MarryKingExpr.as:1731-1758`）。
- `MarryMadamToolTip`：显示妻妾 `command/affairs/bravery/wisdom/introduce`（`MarryMadamToolTip.as:165`）。

### 2.8 好友 `FriendDialog`

**发送链路**（`ChatPanel.as:2220-2412 sendChat`）：
1. 前缀 `/` 语法：`/玩家名 内容` → 切私聊（`:2247-2268`）。
2. 频道校验：联盟需 `User.unionid≠0` 且未屏蔽；战场需 `Global.canChatInBattleChannel()`；Q 版需 `canChatInChibiChannel()`（`:2269-2313`）。
3. 频率限制：`serverTime - mChatTime[0] < 5` 秒 → 提示 `tooFast`（`:2314-2334`，保留最近 3 次发送时间）。
4. 过滤换行/全角空格，空串提示 `emptyStr`（`:2338-2362`）。
5. 组包 `ByteArray(LITTLE_ENDIAN)`：`writeInt(User.uid)`+`writeUTF(User.username)`+`writeInt(toUid)`+`writeUTF(toUser)`+`writeUTF(msg)`（`:2363-2369`）。

## 8. 原版怪癖与注意事项

1. **两套通道并存**：聊天与好友增删走**独立 `ChatSocket`（`flash.net.Socket` 二进制）**，而联盟/排行/统计/结婚/好友列表走**业务 RemoteObject（AMF）**。重写版若只做 REST，需为聊天/好友增删另建长连接通道（或改协议）。
2. **命令名即函数名**：后端 `Command::sendCommand` 用 action 直接 `function_exists` 调用，因此 `module` 只是回显字段；同一函数名可被多个 module 复用（如 `getUnionRelation` 同时被 `union` 与 `union_relation` 调用）。
