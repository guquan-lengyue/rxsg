## 二、方法论：如何从 AS 还原逻辑

### 2.1 资源 ↔ 脚本的三条绑定（决定"美术资源的作用"）
| 机制 | 表现 | 还原方法 |
|---|---|---|
| A `[Embed]` | 类继承 `BitmapAsset`，`[Embed(source="/_assets/<ID>_<类名>.png")]` | `symbolClass/symbols.csv` 查 `字符ID → 类名`；位图在 `images/<ID>_<类名>.png` |
| B 具名链接类 | `new ClassName()` / `getDefinitionByName` | shape/sprite 目录 + `symbols.csv`；命名 `<父>_$<部件>`（如按钮三态 `*_up/_over/_down`） |
| C 运行时 URL | 拼字符串后在 `Loader` 中加载 | 搜 `Global.getImagePathFunc()` / `getImagePath` / `".png"` / `".jpg"`，记录命名规则 |

> 判断"某张图属于哪个界面"的可靠路径：**先找引用它的脚本**（机制 A/B 可由类名反查；机制 C 由拼接语句所在类反查），再看该脚本属于哪个弹窗/面板类。

### 2.2 页面逻辑（弹窗/面板如何组织）
- 入口：主壳 `BloodWar.as` 的 `onGlobalCommand`/`onDialogCommand`；底栏/顶栏按钮（`Bar/`）；建筑点击（`CityInnerPanel` → `BuildingGrid`）
- 面板类名规律：`*Panel`（常驻面板）、`*Dialog`（弹窗）、`*Item`（列表项）
- 弹窗注册：`PopupDialog`/`AlertPanel`（`utils/`）、`Global` 中的 dialog 管理器

### 2.3 交互逻辑（点击 → 命令 → 回包 → UI 变化）
必须还原的链路：
```
控件(按钮/输入/列表项) → 事件处理函数 → sendDialogCommand / sendGlobalCommand(命令ID, 参数)
→ 宿主 HTML 的 AMF(amfphp gateway) → 后端 server/game/*.php
→ 回包(COMMAND_TYPE_DIALOG=1 / GLOBAL=2) → onDialogCommand/onGlobalCommand → 回填哪个控件
```
- 命令 ID 常量：`Command.as` / `Define.as`（如 `ID_REPORT_DIALOG=101`、`ID_TACTICS_DIALOG=102`）
- 状态来源：`User.as`（玩家）、`City.as`（城池）、`Global.as`（全局）；客户端只做展示与校验，**权威数值在服务端**

### 2.4 字段还原
对每个界面列出：显示字段 → 数据来源字段（AS 变量名）→ 后端返回字段名。凡 AS 中出现的**文案**（`lang`/硬编码中文）应原样摘录，供重写版比对。

## 四、硬性要求（所有域文档一致）

1. **可追溯**：每条结论给出 `文件:行`（相对 `tools/export/` 的路径）；无法确认的写「待确认」，**禁止臆测**。
2. **类清单要穷尽**：`scripts/` 下该域的全部业务类都要出现（`mx/` 框架类可归类说明不逐个展开）；`*WatcherSetupUtil` 等 Flex 自动生成类可合并成一行说明。
3. **命令链路必须闭环**：控件 → 命令 ID/参数 → 后端函数 → 回包字段 → UI 变化；缺失环节标注「未在 AS 中找到」。
4. **文案原样**：AS 中出现的提示文案/标签，照抄原文（供重写版核对）。
5. **美术引用要落到文件名**：机制 C 的命名规则给出拼接代码所在位置；机制 A/B 给出符号类名与位图文件名。
6. **只写本目录的 markdown**：不改动 `backend/`、`frontend/`、`server/`、`tools/`；不生成其它文件。
7. **重写版对照**：第 7 节必须与 [复刻对照表.md](../docs/复刻对照表.md) 的模块状态对齐（已实现/裁剪/未实现）。
