## 4. 状态机与流程

### 4.1 幸运宝匣
`onCreate`（关闭按钮+8 格 GlowTween）→ 发 `getGoods` → `newRound`：
- `mWinType==-1`（未开奖）：按钮 `LotteryStart`，可点“开始”。
- `mWinType!=-1`（已开奖）：定位中奖格并高亮，`mRestartCount==0`→按钮变 `LotteryGet`（领奖）+重开可用（`enableRestartBtn`）；`mRestartCount>=1`→自动发 `autoGetReward` 弹掉落，`mNewRoundGoods` 记新盘面。
- 开始 → `startLottery` 回包 → `mWinType==-1` 且 `mWinId==-1`→`Lottery_NoMoney` / `==-2`→`Lottery_FullPlayCount`（复位按钮）；否则 `startTimer` 转动 → 命中 → 领奖/自动开新盘。
- 关闭：`hide()`（定时器仍在跑，见 §8）。

## 8. 原版怪癖与注意事项

1. **命令通道名被丢弃**：`Command.php:104-123` 中 `type==2`（global）会 `array_shift` 掉通道名，仅作回包标签；真实分发靠第二参函数名 `function_exists`。故 `campaign`/`ArenaBattle`/`ArenaCrossBattle` 三个通道共用同一函数命名空间（如 `getAllHeroByUid` 唯一），不会冲突。
2. **抽奖默认不可用是 1:1 复刻**：`checkLottoryTime:669-679` 时间窗判断被注释，恒 `throw not_available_time`（对照表 267 行已核实原文件）。
3. **`useMoney` 命令恒为占位**：前端 `MainDialog.as:414` 发 `lottery/useMoney` 无参，后端 `useMoney:609` 的 `$count>1` 对 `null` 为假 → 直接返回 `[1]`，不扣元宝（扣款实际在 `startLottery:100-114` 用道具抵扣）。
4. **`checkLotteryMoney` 注释与实现不符**：`LotteryFunc.php:598` 注释"消耗10个元宝"，实际 `$use_money=6`（`:598/612`）。
5. **抽奖“次数”实为 1 小时窗内计数**：`getTodayCount:201-208` 用 `unix_timestamp()-time<=3600`（近 1 小时），非自然日；且“第一次免费，第二次起扣道具”（`startLottery:100`），与 UI `Lottery_PlayCount` 文案存在语义张力。
6. **`randWin` 双重去重**：`LotteryFunc.php:218-300` 对上一轮中奖 `last_win_id/type` 连续尝试两次跳过，保证不重复中同一物；抽奖池 `getAllLevelGoods:343` 生成顺序 1,2,3,7,8,4,5,6 并“保 8 格”，7/8 等强制 `type=1`（装备）。
7. **洛阳派兵时段注释与代码不一致**：`LuoyangFunc.php:17-21` 注释“19点/改成10点、16点”，实际判定 `hour!=8 && hour!=14` 即抛 `out_of_time`。
8. **洛阳归属“年份”逻辑**：`luoyangAllocate:405-415` 用 `count` 累加表示连续持有年份（间断>7 天重置），并给被分配者爵位置为 21 + 王爵 buff `130527`（10 天）。
