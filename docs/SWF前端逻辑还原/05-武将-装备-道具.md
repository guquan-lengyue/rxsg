## 2. 界面结构与字段

> 通用皮肤类：`PopupDialog`(弹窗外框)、`PopupTitle`/`PopupDialogTitle`(标题条)、`BoardListDown`/`BoardListUp`(列表底/顶)、`FramePicture`(图片框)、`ButtonRed/Green/Yellow/Close/Cancel/Confirm/Repair/Renovate/Deify`(按钮三态)。

### 2.1 HeroDetailDialog（武将详情，核心）
六列分区（HeroDetailDialog.as:243-…）：
- **左栏 160px**：`heroListCtrl`(DataGrid 3 列)：`name`(列1, :1705)、`level`(列2, :4581 宽47，renderer 显示 `HeroDetailDialogSrc_18"+level`)、`statename`(列3, :3674)。点击 `itemClick`/双击 `itemDoubleClick` → `onClickHeroItem`(:1961)。
- **中栏 165~448px**：头像框(66×82 `Image2` + `cardFrame` 64×80 品质卡框)、`changeNameButton`(改名, :469) / `showIntroduceButton`(NPC 介绍, 互斥可见 :483)；属性四维文本 `Text1..Text3`+`Label2`；技能位 `armorPanel.heroSkill`；技能名 `skillName`、`skillDes`。
- **右栏**：`armorPanel`(HeroArmorPanel 16 装备位 + 1 技能位)。
- **底部按钮**：`addAffairs/Bravery/Wisdom`(加点)、`saveButton`、`clearPointBtn`(洗点)、`upgradeButton`(升级)、`addExpBtn`(加经验)、`addForceBtn/addEnergyBtn/addCommandBtn/addAttackBtn/addDefenceBtn`(5 个属性丹)、`digestSkillBtn`(技能重置)、`studyButton`(君主)、`summonBtn/releaseBtn/acceptBtn/rejectBtn/dismissBtn`(状态相关)、`goodsButton`(buff/赏赐面板)、`largessBtn`(赏赐)、`changeNameButton`、`Button28`(去商店买装备)。

**字段绑定**（`regenAttribute` :3094-3128 / `updateHero` :2123-2283）：
| 显示 | 数据字段 | 计算 |
|---|---|---|
| `command_text` | `level+command_base`，`buf1>now`→×1.5，`+command_add_on` | :3096 |

### 2.2 HeroArmorPanel + ArmorItemSmall + HeroSkillItemSmall
- `ARMOR_PART`(:39) = `[10,20,30,40,50,60,70,80,90,91,100,101,110,111,112,120,130]`：前 16 为装备部位，第 17(`130`)为技能位。
- `ArmorItemSmall.init(sPart)`(:330)：`ArmorTooltip.ARMOR_PART_NAME[sPart/10-1]` 取部位名，空位显示 `armorslot_null.png`。
- 右键 `menuData`(:43)：`equip`/`offload`/separator/`repair`/`renovate`（空位禁 offload/repair/renovate，满耐久禁 repair/renovate，`onClick` :356）。
- `HeroSkillItemSmall`(同结构) `SkillItem` 菜单只 `equip`/`offload`；图像 `images/heroskill/skill_{skill}_{level}.png`(:233)。
- 面板顶部按钮：`Button1`修复全部(:1117→`onClickRepairAll`)、`Button2`翻新全部(:478→`onClickRenovateAll`)、`Button3`神化(:665→`onClickDeifyArmor`，`hasSomeDeified` 决定提示)、`Button4`卸下全部(:822→`onClickOffloadArmor`)；`setEmpty()`(:417) 全清。

### 2.3 HeroBufferDialog（增益 buffer）
DataGrid 3 列：`name`(:484)、`timeleftSrc`(:420)、第 3 列 renderer 显示剩余操作按钮(:490)。`onHeroBuffer(arr)`(:351)：`timeleft=endtime-getServerTime()`，`timeleftSrc=Utils.MakeTimeLeftString`，`setInterval(onTimer,1000)`(:504) 秒级倒计时，归零 `reLoad(hid)`(:426)。按钮2 赏赐(:451→`onShowLargessPanel`)、按钮3 褒奖(:434→`onShowPraisePanel`)。

### 2.4 改名/介绍/赏赐/褒奖
- `ChangeHeroNameDialog`：标题+原名(Label3←`mHero.name`)+输入框 `newHeroName`。`onChangeName`(:343) 发 `[cid,hid,name]`。
- `IntroduceDialog.onShowNpcIntroduce`(:215)：`text = name [+ "字号:"+zi] + 介绍 + introduce`。

### 2.5 KingInfo / KingInfoItem（君主将）
- `KingInfoItem`：10 级君书槽 `kingLevel1..10` + 激活/未激活图 `activeKingBook_{1..10}.png`/`unActiveKingBook_{n}.png`(:1458/:1462)；`KingBookTipArr` 10 条提示，门槛 `Active_limitLevel` = 1/10/20/…/100。

## 8. 原版怪癖与注意事项

1. **头像路径三分**：列表用 `images/herox/hero_*`（InfoHeroItem.as:358、GroundHeroItem.as:312），详情用 `images/hero/hero_*`（HeroDetailDialog.as:2209），君主本人用 `images/player/player_*`（:2175）。同「武将」却是三个目录，重写时不可混用。
2. **品质卡索引有两套**：详情 `(herotype-20000)/1000`（:3619）；背包 `(gid-200000)/10000`（UserGoodsItem.as:400）。触发条件 `herotype%1000==250 && herotype/10000==2`（:3617）。
3. **`dealWithOtherInfoOfArmor` 是隐式契约**：装备类回包在 `[hid,armorArr,finishOneTie,hasSomeDeified]` 之后**追加 5 段**（装备属性对/镶嵌属性/tie/缔结属性/神化/熔炼），若不解析则镶嵌/缔结/神化数值全空。出处 Global.as:429-513。
4. **`updateHero` 的字段是"双来源"**：`affairs/bravery/wisdom` 由 `base+add` 现场算（:2142-2144），`*_text` 在 `regenAttribute` 里再乘 buffer 系数并加 `*_add_on`；重写需两步而非一步。
5. **加点/洗点是本地暂存 + 保存提交**：`onAddPoint` 只改内存(`pointleft`/四维)并亮 `saveButton`；真正写库在 `onSavePoint`→`addHeroPoint`（:2721/:3254）。洗点先弹 Alert 报 `ceil(level/10)` 消耗。
6. **翻新付费弹窗可复用于三种主体**：`ArmorRenovatePayDialog.onSubmit`(:569) 依 `flag_allObj`/`flag_forHero` 组合分发到 `hero.renovateArmor[WithGift]`、`armor.renovateAllArmor[WithGift]`、`hero.renovateAllArmor[WithGift]` 四条命令。
7. **强化失败有三级文案**：`onCommand "doStrong"` `_loc12_` 1/2/3 → `BlackSmith_StrongFailure{1,2,3}`，其中 1 清零、2 降一级（:2404-2414）；成功 `tianGongFu/qianKun` 勾选时各扣 1。
8. **镶嵌孔态语义**（`set5EmbedPearls` :4953）：0=可镶嵌(`item_equip_default.png`)、1=一号锁、2=二号锁、3=空(透明)、4=三号锁(紫装专属，非紫装报 `ArmorEmbed_not_purple` :5018)。
9. **`selectEmbedPearl` 的消耗分支**（:4991）：孔态 1→`showUseGoodsDialog(0,24)`、2→`(0,25)`、4→`(0,28)`、0 且已有珠→`showUseHuaShiFenDialog(26, count)`（`getNeedCount` 依 gid 档位查表 :5259）。
10. **洗练三模式**（`doXilian` :3215）：0=朱熔（须无 best_quality）、1=青洗（须有 best_quality）、2=洗练（依装备 `type` 1-6 → 需求 1/1/1/2/3/4 个洗练材料）；缺料文案 `xilian_lack_zhurong/qingxi/xilian`、`xilian_exist/not_exist`。
11. **锁未开则先弹开锁**：`sellArmor`/`multipAnalyzeArmor` 遇 `type≥4` 走 `showOpenLockDialog("sellArmor"/"analyArmor"/"multipAnalyArmor"/"unionExchangeArmor")`（ArmorDialog.as:1661/1964/1827/1832），未开锁不发命令。
12. **背包 `sellvalue=value*500`**（MyGoodsDialog.as:1368），而装备售价在 `ArmorDialog.onClickSell` 另算 `max(1,floor(hp/orihp))*value*500`（:2059）——两处公式不同。
13. **属性丹 type 编号**：`onAddAffairs`=44(:1896)、`onAddBravery`=45(:1921)、`onAddWisdom`=46(:2937)、`onAddCommand`=43(:3001)、`onAddForce`=2(:4566)、`onAddEnergy`=3(:3533)、`onAddAttack`=52(:3354)、`onAddDefence`=53(:4532)、`onAddExp`=11(:2776)，均以 `showUseGoodsDialog(0,<type>,[hid])` 打开定向用道具。
14. **装备架扩容**：`useArmorShelf` 走 `showUseGoodsDialog(0,30,null)`（:1548），非独立 armor 命令；回包 `case 30` 调 `armorDialog.setArmorMaxCount`（UseGoodsDialog.as:898）。
15. **`loadHuaxiang` 后端缺失**：`WuhunSelectDialog.as:241` 发 `WuhunHecheng.loadHuaxiang`，`server/game/` 无同名函数（`loadSuipian` 有，GoodsFunc.php:21）。
16. **自动生成类**：`*__embed_mxml_*`(6) 与 `*_inlineComponent*`(6) 为 Flex 编译器产物，仅承载 `[Embed]` 位图与内联渲染器，无独立业务逻辑，重写时按 §5 资源复刻即可。
